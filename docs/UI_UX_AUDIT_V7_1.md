# KT Opportunity UI/UX 전면 점검 보고서 — v7.1

## 1. 점검 범위

이번 점검은 이름 변경만 수행하지 않고 실제 사용 흐름을 기준으로 UI를 다시 검토했다.

점검 화면/상태:

1. 로그인
2. 영업 홈
3. 신규 음식점 검색 + 후보 목록 + 영업 기회 확인
4. 맞춤 제안
5. 후속 상담
6. 상담 이력
7. 상품 기준
8. 로딩/빈 상태

반응형 시뮬레이션 해상도:

- 2560 × 1272 — 초광폭 데스크톱
- 1440 × 900 — 일반 데스크톱/노트북
- 1180 × 820 — 좁은 노트북/브라우저 분할
- 768 × 1024 — 태블릿
- 430 × 932 — 일반 모바일
- 390 × 844 — 소형 모바일

기본 화면은 로그인, 영업 홈, 신규 음식점, 맞춤 제안, 후속 상담, 상담 이력, 상품 기준, 로딩에 더해 빈 상태와 오류 상태까지 10종으로 확장했다. 여기에 태블릿/모바일 3개 폭에서 Drawer 오픈 상태를 별도 검사해 총 63개 화면·viewport·상태 조합을 대표 장문 데이터와 긴 매장명/주소/상품코드로 점검했다.

자동 검사 항목은 문서 가로 오버플로우, 화면 밖 요소, 44px 미만 조작 대상, 12px 미만 실사용 텍스트, 내부 overflow, 모바일 카드 변환 및 Drawer 오픈 상태다. `docs/ui-audit/`에는 시뮬레이터, 결과 JSON, 초광폭/데스크톱/모바일 캡처와 Drawer 캡처가 포함되어 있다.

> 이 검사는 실제 프로젝트 CSS와 실제 컴포넌트 구조를 바탕으로 만든 정적 QA 시뮬레이터다. React 런타임 전체 E2E와 실제 n8n 응답/모바일 가상 키보드까지 재현한 테스트는 아니다. 비즈니스 로직은 별도로 `node scripts/smoke.mjs`를 통과했다.

## 2. 발견된 주요 문제와 조치

### A. 브랜드/명칭

문제:
- Sidebar, HTML title, README, 배포 문서 등에 `Opportunity`, `Opportunity Agent`, `kt-sales-agent` 계열 명칭이 혼재했다.

조치:
- 사용자 노출 이름을 `KT Opportunity`로 통일했다.
- 패키지명은 `kt-opportunity`, 버전은 `0.7.1`로 변경했다.
- Nginx 배포 경로를 `/var/www/kt-opportunity`로 변경했다.
- 브라우저 저장 키도 `kt-opportunity:*`로 변경하되 기존 `kt-restaurant-agent:*` 데이터를 자동 읽어 마이그레이션하도록 하여 기존 PoC 이력을 잃지 않게 했다.

### B. 타이포그래피/가독성

문제:
- 보조 설명과 메타 정보가 10~12px에 과도하게 몰려 있었다.
- `--ink-400: #949494`는 흰 배경에서 작은 텍스트 대비가 약했다.
- 매장명이 한 줄 ellipsis로 잘려 실제 후보 구분이 어려울 수 있었다.

조치:
- 실사용 텍스트를 원칙적으로 12px 이상으로 조정하고 주요 메타 정보는 13px로 상향했다.
- `--ink-400`을 `#767676`, `--ink-500`을 `#666666`으로 조정했다.
- 후보 매장명은 한 줄 강제 생략 대신 최대 2줄 자연 줄바꿈으로 변경했다.
- 한국어 `word-break: keep-all`, `overflow-wrap`, `text-wrap` 정책은 유지했다.

최종 시뮬레이션에서는 QA용 우측 상단 라벨을 제외하면 12px 미만 실사용 텍스트가 검출되지 않았다.

### C. Sidebar / Topbar

문제:
- 1180px 구간에서 Sidebar가 222px로 줄어 `KT Opportunity`가 미세하게 잘릴 수 있었다.
- 모바일 Drawer가 열려도 하단 Navigation의 z-index가 더 높아 Drawer 위에 남을 수 있었다.
- 메뉴 버튼이 열림/닫힘 상태를 스크린리더에 전달하지 않았다.
- 로그아웃 버튼의 높이가 44px 미만이었다.

조치:
- 1180px 구간 Sidebar를 236px로 보정했다.
- 모바일 Drawer 오픈 시 하단 Navigation을 비활성/비표시 처리한다.
- 메뉴 버튼에 `aria-expanded`, `aria-controls`, 열기/닫기 레이블, 아이콘 상태를 연결했다.
- Drawer 내부에 명시적인 44px 닫기 버튼을 추가했다.
- 닫힌 모바일 Drawer는 `inert` + `aria-hidden` 처리해 화면 밖 메뉴가 Tab 순서에 남지 않게 했다.
- Drawer가 열리면 첫 조작 대상으로 포커스를 옮기고 Tab/Shift+Tab을 Drawer 안에서 순환시키며, ESC/닫기 시 메뉴 버튼으로 포커스를 복귀한다.
- Drawer 오픈 중 body scroll을 잠근다.
- 본문 바로가기 Skip Link를 추가하고 메뉴 이동 후 본문으로 포커스를 전달한다.
- 아이콘/텍스트 버튼의 최소 조작 영역을 44px로 보강했다.

### D. 모바일 하단 Navigation

문제:
- 기존에는 홈/신규/후속 3개만 존재해 상담 이력과 상품 기준은 Drawer를 거쳐야 했다.
- 현재 페이지가 이력/상품일 때 하단 Navigation에 활성 상태가 표시되지 않았다.

조치:
- 홈 / 신규 / 후속 / 이력 / 상품 5개 영역을 모두 노출했다.
- 모바일 폭에서도 5분할이 유지되도록 레이블을 짧게 정리했다.
- iPhone 계열 Safe Area를 고려해 `env(safe-area-inset-bottom)`을 적용했다.

### E. 로그인

문제:
- 모바일에서 브랜드 설명 영역이 길어 실제 시작 CTA가 첫 화면 아래로 밀릴 가능성이 높았다.
- 3단계 소개 Flow가 모바일에서 세로 공간을 과도하게 사용했다.

조치:
- 760px 이하에서는 소개 Flow를 숨기고 브랜드 설명 영역을 압축했다.
- 430 × 932 시뮬레이션 기준 시작 CTA가 첫 화면 안에 들어오도록 정리했다.
- 긴 환경 정보 텍스트는 자연 줄바꿈을 유지했다.

### F. 영업 홈

문제:
- 1180px 이하에서 정적인 `업무 흐름` 패널이 실제 신규 음식점 목록보다 먼저 배치되는 구조였다.
- 메트릭 보조 문구가 작고 옅었다.

조치:
- 화면이 좁아져 1열이 되더라도 `최근 신규 음식점`이 먼저 나타나도록 원래 정보 우선순서를 유지했다.
- 메트릭 및 Human verified 설명의 크기/대비를 상향했다.

### G. 신규 음식점 검색

문제:
- Desktop 3열 Filter Grid에 6개 필드 + 조회 버튼이 들어가 조회 버튼만 3번째 줄 한 칸에 남는 어색한 배치였다.
- 모바일에서 Filter가 기본 펼침이라 실제 후보를 보기 전 첫 화면 대부분이 검색 폼으로 채워졌다.
- 자연어 검색 입력 높이가 40px로 Tablet Touch Target 기준이 부족했다.

조치:
- 조회 버튼을 Filter Grid 전체 폭의 별도 Action Row로 이동하고 우측 정렬했다.
- 760px 이하에서는 상세 검색 조건을 기본 접힘으로 시작한다.
- 버튼 문구를 `검색 조건 펼치기 / 검색 조건 접기`로 상태에 맞게 변경했다.
- 자연어 입력 영역 높이를 44px로 올렸다.

### H. 후보 목록 / Master–Detail

문제:
- 1180px에서 목록 310px + 상세 화면을 강제로 나누면 양쪽 모두 좁아졌다.
- 긴 매장명이 한 줄 ellipsis로 잘렸다.
- 모바일/태블릿 전환 시 Sticky 목록이 과도하게 공간을 차지할 수 있었다.

조치:
- 1180px 이하에서는 Master–Detail을 1열로 전환했다.
- 후보 목록 내부는 최대 높이 380px(소형 모바일 340px)로 제한해 상세 화면까지 지나치게 멀어지지 않게 했다.
- 매장명은 2줄까지 허용했다.

### I. 영업 기회 확인

문제:
- `관리번호`가 다른 Fact와 같은 폭을 사용해 끝부분만 어색하게 줄바꿈될 가능성이 있었다.
- `맞춤 제안 만들기`가 비활성일 때 사용자가 왜 비활성인지 바로 알기 어려웠다.
- 분석 근거/결정 규칙 텍스트가 상대적으로 작았다.

조치:
- Store Fact 4열 중 관리번호 열을 더 넓게 할당했다.
- CTA 비활성 상태에 `추천 가능 항목이 생기면...` 안내 문구를 추가했다.
- 분석/결정 규칙 설명을 13px 수준으로 상향했다.

### J. 맞춤 제안

문제:
- 상품 코드, 가입 조건, 검수일 등 실무 확인 정보가 11~12px 위주였다.
- 작은 화면에서 상품 Header/코드가 길 경우 시각 밀도가 높았다.

조치:
- 상품 메타 정보 크기와 대비를 상향했다.
- 긴 상품코드에 `overflow-wrap`을 적용했다.
- 제안 Hero는 1180px 이하에서 1열로 전환하고 CTA/우선순위 영역을 아래로 배치한다.

### K. 후속 상담

문제:
- 사용자 동의 Checkbox 자체가 시각적으로 숨겨져 있어 Keyboard focus가 명확하지 않았다.
- 모바일에서 추천 상품 코드의 우측 정렬이 어색할 수 있었다.

조치:
- `.approval-box:focus-within` focus ring을 추가했다.
- 모바일에서는 추천 코드 목록을 좌측 정렬한다.
- 입력창/Select는 모바일 16px을 유지해 iOS 자동 확대를 방지한다.

### L. 상담 이력

문제:
- 기존 Table은 `min-width: 940px`이라 모바일에서 필수 가로 스크롤이 발생했다.
- 1180px 환경에서도 Sidebar를 포함하면 몇십 px 가로 Scroll이 남을 수 있었다.
- Lead/상담 상태가 일반 텍스트라 긴 행을 빠르게 스캔하기 어려웠다.

조치:
- Desktop Table 최소폭을 820px로 축소했다.
- 760px 이하에서는 Table을 카드형 Key–Value Row로 변환한다.
- 각 `<td>`에 `data-label`을 부여해 모바일에서도 항목 의미가 유지된다.
- Lead/상담 상태를 Status Badge로 변경했다.

### M. 상품 기준

문제:
- 중간 폭에서도 5열 Definition Grid를 유지해 가입 조건/혜택 문장이 과도하게 좁아질 수 있었다.
- 코드/검수 정보가 11~12px이었다.

조치:
- 1180px 이하 3열 → 760px 이하 2열 → 540px 이하 1열로 단계적으로 전환한다.
- 모바일 Product Header도 재배치해 상품명/코드/유효 Badge가 충돌하지 않게 했다.
- 메타 정보 크기/대비를 상향했다.

### N. Loading / Empty / Error 상태

문제:
- 로딩 단계가 길어질 경우 작은 화면에서 Card 자체가 화면 아래로 잘릴 수 있었다.
- Empty State의 320px 고정 최소 높이는 모바일에서 불필요하게 길었다.

조치:
- Loading Card에 `max-height: calc(100dvh - 40px)` 및 내부 Scroll을 적용했다.
- 540px 이하 Empty State 최소 높이를 220px로 축소했다.
- `prefers-reduced-motion` 지원은 유지했다.

## 3. 최종 시뮬레이션 결과

63개 화면·viewport·상태 조합에서 다음 항목을 다시 검사했다.

| 검사 항목 | 결과 |
|---|---:|
| 문서 전체 가로 overflow | 0 / 63 |
| 44px 미만의 보이는 실제 조작 대상 | 0 |
| 12px 미만 실사용 텍스트 | 0 |
| 모바일 상담 이력 가로 Table 강제 | 제거 완료 |
| 모바일 5개 주요 메뉴 접근 | 완료 |
| 1180px Sidebar 브랜드 잘림 | 제거 완료 |

자동 검사에서 남는 overflow 표시는 아래 두 종류뿐이며 의도된 동작이다.

- 로그인/Hero의 장식용 원형 pseudo element가 부모 `overflow:hidden`에 의해 잘리는 경우
- 모바일 상담 이력에서 접근성 목적으로 화면 밖에 숨긴 `<thead>`

모바일 Drawer는 닫힌 상태에서 화면 왼쪽 밖으로 `transform`되므로 DOM Bounding Rect 검사에는 화면 밖 요소로 잡히지만 문서 전체 가로폭을 늘리지는 않는다.

## 4. 실제 기기에서 추가 확인할 항목

정적 시뮬레이션 이후에도 배포 전에 아래는 실제 기기/브라우저 확인이 필요하다.

- iOS Safari 주소창 축소/확대 시 `100dvh` 및 하단 Safe Area
- Android Chrome 가상 키보드가 열린 상태에서 Fixed Bottom Navigation
- n8n 응답이 3~5배 길어질 때 Error/Loading/Proposal 본문
- 실제 서버에서 내려오는 가장 긴 사업장명·주소·상품명·가입조건
- 네트워크 지연/Timeout/401 재로그인 시 Focus 이동
- 실제 키보드/스크린리더 조합에서 Skip Link, Drawer Focus Trap, 상태 알림 읽기 순서 재확인

코드 수준에서는 Drawer Focus Trap, 닫힌 Drawer `inert`, ESC 닫기, Background scroll lock, 포커스 복귀까지 구현했다. 남은 항목은 실제 브라우저/보조기술 조합에서의 동작 확인이다.
